# fail2ban-rs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sshd の認証失敗を journal から読み、連続して失敗する IP を nftables で一定時間ブロックする Rust 製の単一バイナリを作る。

**Architecture:** `journalctl -f -o json` を子プロセスで読むスレッドが `LogEntry` をチャネルに流し、メインスレッドの `Engine` がフィルタ → ignoreip → スライディングウィンドウ → `BanAction` の順に処理する。ブロックは nft の timeout 付き set に入れ、解除はカーネルに任せる。各段は純粋な関数か、注入できる trait にしてテストする。

**Tech Stack:** Rust edition 2024 / fancy-regex 0.19 / serde + serde_json / toml / clap 4 (derive) / ipnet / thiserror。非同期ランタイムは使わない (std のスレッドと mpsc)。

**Spec:** `docs/superpowers/specs/2026-10-20-fail2ban-rs-design.md` (上流の式は `docs/upstream/sshd.conf`)

## Global Constraints

- crate 名・バイナリ名: `fail2ban-rs`。`edition = "2024"`。`license = "GPL-2.0-or-later"`。
- 依存はこの 7 つ (+ dev 用は `tempfile` のみ可): `fancy-regex = "0.19"`, `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`, `toml = "0.9"`, `clap = { version = "4", features = ["derive"] }`, `ipnet = "2"`, `thiserror = "2"`。
- 対象: `x86_64-unknown-linux-musl` と `aarch64-unknown-linux-musl`。libsystemd などの C ライブラリにリンクしない。
- テスト以外のコードで `unwrap()` / `expect()` を使わない。エラーは `Result` で返し、stderr に出して続けるか終了コード 1 で止める。
- 1 ファイル 400 行以内。コメントと README は日本語。絵文字は使わない。
- 正規表現は `fancy_regex::RegexBuilder` で `backtrack_limit(100_000)` を付けて作る (ログの行は攻撃者が書ける)。
- 各タスクの最後に `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test` が通ること。
- 既定値: maxretry 5 / findtime 600 秒 / bantime 600 秒 / mode `log` / ignoreip `["127.0.0.0/8", "::1"]` / journalmatch `["_COMM=sshd", "+", "_COMM=sshd-session"]` / table `fail2ban_rs` / priority -10 / nft_path `/usr/sbin/nft` / journalctl_path `/usr/bin/journalctl`。

## Review Focus

- `::ffff:192.0.2.1` のような IPv4 射影アドレス → IPv4 として数え、ignoreip も IPv4 で判定し、nft の `addr4` に入る。(Task 3 にテスト)
- journal の `MESSAGE` が数値の配列 (バイト列) で来る → UTF-8 として (不正部分は置き換えて) 読む。(Task 7 にテスト)
- `nft` が無い・構文を受け付けない → `start()` が nft の stderr を含むエラーを返し、`run` は終了コード 1 で止まる。(Task 8 にテスト)
- journalctl が途中で終わる → 最後の `__CURSOR` から `--after-cursor` で再開し、同じ行を二重に数えない。(Task 7 にテスト)
- ignoreip に入る IP が maxretry を超えて失敗する → 数えず、ブロックもしない。(Task 9 にテスト)

### Task 4: sshd フィルタ (normal モード)

**Model:** sonnet

**Files:**
- Create: `src/filter/mod.rs`, `src/filter/expand.rs`, `src/filter/sshd.rs`
- Test: `tests/filter_test.rs`

**Interfaces:**
- Produces:
  - `pub fn expand(template: &str, vars: &[(&str, &str)]) -> String` (`src/filter/expand.rs`)
  - `#[derive(Debug, Clone, PartialEq)] pub struct FilterMatch { pub host: String, pub user: Option<String>, pub nofail: bool }`
  - `pub struct SshdFilter` / `impl SshdFilter { pub fn new() -> Result<Self, FilterError>; pub fn check(&self, message: &str) -> Option<FilterMatch> }`
  - `#[derive(Debug, thiserror::Error)] pub enum FilterError`

**展開の規則 (`expand`)** — 上流の `failregex.py` と `sshd.conf` に合わせる:
- `%(name)s` と `<name>` は `vars` の値に置き換える。値の中の参照も、置き換えが無くなるまで繰り返す (上限 10 回)。
- `<HOST>` → `(?:\[?(?:(?:::f{4,6}:)?(?P<ip4>(?:\d{1,3}\.){3}\d{1,3})|(?P<ip6>(?:[0-9a-fA-F]{1,4}::?|:){1,7}(?:[0-9a-fA-F]{1,4}|(?<=:):)))\]?|(?P<dns>[\w\-.^_]*\w))`
- `<ADDR>` → 上の式から `|(?P<dns>…)` を除いたもの。
- `<F-NOFAIL>` → `(?P<nofail>`、`<F-USER>` → `(?P<user>`、`<F-ALT_USER>` → `(?P<alt_user>`、その他の `<F-XXX>` (MLFFORGET, MLFGAINED など) → `(?:`。すべての `</F-XXX>` → `)`。

**式の一覧** (`src/filter/sshd.rs`) — `docs/upstream/sshd.conf` の `[DEFAULT]` の変数 (`__pref`, `__on_port_opt`, `__suff`, `__authng_user`, `__alg_match`, `__pam_auth`) と、`publickey = nofail`、`mode = normal` のときの `failregex` をそのまま写す。順番は上流と同じ: `cmnfailre` の 19 行 (`<cmnfailre-failed-pub-<publickey>>` は `cmnfailre-failed-pub-invalid` の式に、`<cmnfailed>` は `cmnfailed-nofail` の式に、`<mdre-<mode>-other>` は `mdre-normal-other` の式に置き換える) → `cfooterre`。`mdre-normal` は空なので入れない。空の式は捨てる。

**`check` の手順:**
1. `message` の先頭の `^(?:(?:error|fatal): (?:PAM: )?)?` を外す (上流の `prefregex` の `__pref`)。
2. 式を上から順に試し、最初に当たったものを採る。`backtrack_limit` を超えたなどの実行時のエラーは「当たらなかった」とみなす。
3. `host` は `ip4` / `ip6` / `dns` のうち当たったもの。`user` は `user` の群。`nofail` は `nofail` の群が当たったかどうか。

- [ ] **Step 1: 失敗するテストを書く** (いずれも `SshdFilter::new()?.check(msg)` の結果)
  - `"Failed password for invalid user admin from 192.0.2.7 port 4242 ssh2"` → `host "192.0.2.7"`, `user Some("admin")`, `nofail false`
  - `"Failed password for root from 2001:db8::5 port 22 ssh2"` → `host "2001:db8::5"`, `user Some("root")`
  - `"error: PAM: Authentication failure for bob from 192.0.2.8"` → `host "192.0.2.8"`, `nofail false`
  - `"Invalid user test from 192.0.2.9 port 5555"` → `host "192.0.2.9"`, `user Some("test")`
  - `"Failed publickey for invalid user x from 192.0.2.10 port 1 ssh2"` → `nofail false` (invalid user の公開鍵は失敗)
  - `"Failed publickey for alice from 192.0.2.11 port 1 ssh2"` → `nofail true`
  - `"Accepted publickey for densuke from 192.168.11.5 port 52759 ssh2: RSA SHA256:x"` → `nofail` 以外の当たり方をしない (`None` か `nofail true`)
  - `"Connection closed by authenticating user densuke 192.168.11.5 port 52755 [preauth]"` → `None` か `nofail true`
  - `"pam_unix(sshd:session): session opened for user densuke(uid=1000) by densuke(uid=0)"` → `None`
  - 攻撃者の書いた長い行: `format!("Failed password for invalid user {} from 192.0.2.12 port 1 ssh2", "a ".repeat(5000))` で `check` が panic せずに返る (結果は問わない)
  - `expand("<a>-%(b)s", &[("a", "<b>"), ("b", "x")]) == "x-x"`
- [ ] **Step 2:** 失敗を確かめる。
- [ ] **Step 3:** 実装する。
- [ ] **Step 4:** テストが通る。
- [ ] **Step 5:** Commit `feat: sshd フィルタ (fail2ban の normal モードの移植)`

### Task 7: journal の読み取り

**Model:** sonnet

**Files:**
- Create: `src/journal.rs`
- Test: `tests/journal_test.rs`

**Interfaces:**
- Produces:
  - `#[derive(Debug, Clone, PartialEq)] pub struct LogEntry { pub time: SystemTime, pub message: String, pub cursor: Option<String> }`
  - `pub fn parse_journal_json(line: &str) -> Option<LogEntry>` — `__REALTIME_TIMESTAMP` (マイクロ秒の 10 進文字列) を時刻に、`MESSAGE` (文字列か、数値の配列 = バイト列) を本文に、`__CURSOR` をカーソルにする。JSON が壊れている、時刻か本文が無いときは `None`。
  - `pub fn journalctl_args(matches: &[String], findtime: Duration, after_cursor: Option<&str>) -> Vec<String>` — `["-f", "-o", "json", "--no-pager"]` に、カーソルが無ければ `"--since=-<findtime の秒>s"`、あれば `"--after-cursor=<cursor>"` を足し、最後に `matches` を続ける。
  - `pub fn spawn_reader(journalctl: PathBuf, matches: Vec<String>, findtime: Duration, tx: std::sync::mpsc::Sender<LogEntry>) -> std::thread::JoinHandle<()>` — journalctl を起動して標準出力を 1 行ずつ `parse_journal_json` に通し、送る。journalctl が終わったら stderr に理由を出し、5 秒待って、最後に見たカーソルで起動し直す。`tx` の送信が失敗したら (受け手が終わったら) スレッドを終える。

- [ ] **Step 1: 失敗するテストを書く**
  - `{"__REALTIME_TIMESTAMP":"1792304167216173","MESSAGE":"Failed password for root from 192.0.2.1 port 1 ssh2","__CURSOR":"s=abc"}` → time = `UNIX_EPOCH + 1792304167216173µs`、message、`cursor Some("s=abc")`

  - `MESSAGE` が無い、`__REALTIME_TIMESTAMP` が数字でない、`not json` → `None`
  - `journalctl_args(&["_COMM=sshd".into(), "+".into(), "_COMM=sshd-session".into()], 600s, None) == ["-f","-o","json","--no-pager","--since=-600s","_COMM=sshd","+","_COMM=sshd-session"]`

  - `spawn_reader` の再開: journalctl の代わりに、テストで書いたシェルスクリプト (`tempfile` の中) を渡す。スクリプトは、引数に `--after-cursor=` が無ければカーソル `c1` の行を 1 行出して終わり、あれば受け取ったカーソルを `MESSAGE` に入れた行を 1 行出して `sleep 30` する。受信した 2 件目の `message` が `"--after-cursor=c1"` を含むことを確かめる (受信は `recv_timeout(15s)`)。

### Task 9: Engine と CLI

**Model:** sonnet

**Files:**

- Modify: `src/main.rs`

**Interfaces:**
- Consumes: `Config`, `load_config` (Task 2), `IgnoreList`, `canonical_ip` (Task 3), `SshdFilter` (Task 4), `FailTracker` (Task 6), `LogEntry`, `spawn_reader` (Task 7), `BanAction`, `LogAction`, `NftAction` (Task 8)
- Produces:
  - `#[derive(Debug, Clone, PartialEq)] pub enum Outcome { NoMatch, Unresolvable(String), Ignored(IpAddr), Counted(IpAddr), Banned(IpAddr) }`
  - `pub struct Engine<A: BanAction>` / `impl<A: BanAction> Engine<A> { pub fn new(config: &Config, action: A) -> Result<Self, EngineError>; pub fn handle(&mut self, entry: &LogEntry) -> Result<Outcome, ActionError>; pub fn prune(&mut self, now: SystemTime) }`

**`handle` の順番:** フィルタが `None` か `nofail` → `NoMatch`。`canonical_ip` が `None` → `Unresolvable(host)`。ignoreip に入る → `Ignored`。`tracker.record(ip, entry.time)` が `true` → `action.ban(ip, bantime)` して `Banned`。それ以外 → `Counted`。

**`main.rs` (clap):**
- `run [--config PATH]` (既定 `/etc/fail2ban-rs/config.toml`): 設定を読む → `sshd.enabled` が false なら終わる → mode に応じた `BanAction` を作って `start()` (失敗したら stderr に出して終了コード 1) → `spawn_reader` → `recv_timeout(60s)` で受けて `handle`。結果が `Banned` なら `ban <ip> for <秒>s`、`Ignored` なら `ignored <ip>` を標準出力へ。`handle` の `Err` は stderr に出して続ける。タイムアウトのたびと、1,000 件ごとに `prune(SystemTime::now())`。
- `test-filter [FILE]`: 1 行ずつ `SshdFilter::check` に通し、`fail <host> user=<user>` / `nofail <host>` / (当たらなければ出さない) を出す。最後に `matched N/M lines`。
- `check-config [--config PATH]`: 読んで検証し、実際に使う値を `{:#?}` で出す。
